## Authoritative purchase validation

Sources: [Get Validation Violations](https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/extensions/validations/validations-integration-service-plugin/get-validation-violations), [extension config](https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/extensions/validations/validations-integration-service-plugin/extension-config), [CLI guide](https://dev.wix.com/docs/build-apps/develop-your-app/develop-an-app-with-the-cli/supported-extensions/backend/service-plugins/add-service-plugin-extensions-with-the-wix-cli), [handler files](https://dev.wix.com/docs/build-apps/develop-your-app/develop-an-app-with-the-cli/supported-extensions/backend/service-plugins/service-plugin-extension-files-and-code).

- CLI schema supports `SERVICE_PLUGIN` with `pluginType: ECOM_VALIDATIONS`. Generated handler calls `validations.provideHandlers({getValidationViolations: async ({request, metadata}) => ...})` from `@wix/ecom/service-plugins`.
- Installed Astro builder supports `extensions.ecomValidations({id, name, source, validateInCart})`. Set `validateInCart: true`. Do not copy the generator's false default.
- Callback receives validationInfo.lineItems (maximum 300), catalogReference, quantities, and buyerDetails with email/contactId. Source info identifies CART/CHECKOUT/OTHER plus purchaseFlowId.
- REST response is `{violations: [{severity: "ERROR", target: {lineItem: {id, name: "LINE_ITEM_DEFAULT"}}, description}]}`. General error targets use other.name OTHER_DEFAULT. SDK ID mapping (`_id` versus `id`) must be verified against the installed ecom package before writing the handler. The local example omits the target name; use the full contract instead.
- ERROR blocks cart progression or checkout order placement. WARNING allows progression. Description is 1–1000 characters. Use localized plain text with escaped substitutions.
- Do not call Estimate Cart Totals, Estimate Current Cart Totals, or Get Checkout inside this callback; official schema warns of errors/recursive flow.
- Evaluate launchUTC <= now and now < endUTC directly on the server. Cancel/restore/uninstall exemptions precede enforcement. Scheduler status is never the authoritative gate. Only target matching Stores catalog products.
- Products remain visible. This API does not document disabling native Add to Cart. The widget must state unavailability clearly.
- An explicit memberId is absent from the retrieved business request schema. Official introduction lists members-only as a use case but does not establish a reliable guest/member distinction here. Inspect authenticated invocation metadata and test members/guests before enabling the feature. Contact ID alone does not prove membership.
- No numeric timeout or platform fail-closed behavior for this eCommerce SPI was established. Searches also returned Bookings fail-closed docs; they are not evidence for eCommerce. An app can return ERROR on an observed Data failure, but cannot promise blocking if Wix never invokes it or ignores a timed-out callback. This is a production acceptance blocker pending live verification/Wix clarification.
- No transaction couples validation with eventual order creation. Concurrent carts, delayed order events, guest identity changes, and other sales channels prevent a strict per-person guarantee. Document best-effort limits and test bypass paths.
- The CLI guide requires build/release before new/changed service plugins take effect. A green local build or preview cannot prove checkout gating.

## Open gates before enabling features

1. Resolve SDK versions/aliases, service-plugin authenticated tenant/member/locale metadata, and target ID transformation.
2. Verify merchant mutation authorization and visitor public endpoint site binding with adversarial cross-tenant tests.
3. Verify conditional-write conflict behavior, index readiness/capabilities, quotas, retention/uninstall cleanup, and deterministic-ID errors on real app collections.
4. Obtain live V1/V3 test sites and release evidence. Measure callback latency with 300 line items. Obtain Wix eCommerce timeout/failure behavior confirmation.
5. Verify remaining event payloads, order/transaction backfill APIs, inventory location policy, and non-native checkout channel coverage.
6. Decide notification trigger/provider, bot-protection contract, consent/double opt-in policy, suppression, retry/idempotency provider behavior, and retention.
7. Disable catalog pricing until safe restoration (especially V1), currencies and discount interactions are proven. Document this as an unavailable option rather than replacing it with mock behavior.
8. Verify App Market listing/billing setup, privacy policy, browser/editor/published behavior, and 20-language translation quality. Production demo seeding is expressly forbidden by this request.
